# Reddy OTA 升级

## 升级流程

1. 设备联网后请求 `CONFIG_OTA_URL`，携带设备 ID、板型和当前版本。
2. 服务端按板型、版本、灰度比例和最低安全版本生成升级响应。
3. 设备确认响应包含版本、文件大小和 64 位 SHA-256。
4. 固件下载到当前未运行的 OTA 分区，同时计算 SHA-256。
5. 设备核对实际长度、SHA-256、ESP 项目名和固件内嵌版本。
6. 校验全部通过后切换启动分区并重启。
7. 新固件启动且网络初始化成功后确认分区；此前崩溃则自动回滚。

OTA 服务检查失败只会进行一次短重试，不阻塞设备进入正常语音服务。

## 首次启用

旧版自定义 WebSocket 固件会跳过 OTA 检查，因此需要通过 USB 烧录一次
2.3.0。此后可直接通过 OTA 发布后续版本。

## 服务端发布

服务端源码位于 GitHub 的 `reddy-server` 分支。网页发布入口为 `/ota`，
也可以使用该分支中的 `publish_firmware.py`。

发布操作需要 `OTA_ADMIN_TOKEN`。令牌只存放在服务器 `.env`，不能写入固件
或提交到 Git。服务端发布前会解析 `esp_app_desc_t`，要求：

- 文件是有效的 ESP 应用镜像；
- 项目名为 `xiaozhi`；
- 表单版本与固件内嵌版本一致；
- 文件不超过设备 OTA 分区的 6 MiB 上限。

## 回滚

项目启用了 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`，分区表包含
`ota_0` 和 `ota_1` 两个 6 MiB 应用分区。设备只在显示、音频和网络初始化
成功后调用确认接口，因此无法完成基本启动的新固件不会成为永久版本。
